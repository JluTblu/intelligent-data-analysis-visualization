# Datas

Проект курса «Интеллектуальный анализ и визуализация данных», ML-трек: приложение Taipy для анализа карточек SOC и результатов модели.

## Данные

Обновлённый набор `iavd_ml_dataset.parquet` взят из материалов занятия 3.6 и хранится в `data/raw/`. Словарь полей из тех же материалов находится рядом. Parquet-файлы хранятся через Git LFS.

Учебная бинарная метка по словарю: `y = 1` для вердикта «Решён», `y = 0` для `False Positive`; остальные вердикты не входят в эту бинарную выборку. Поля, появляющиеся после начала расследования, нельзя использовать как признаки.

## Текущий результат

- `scripts/prepare_binary_dataset.py` формирует промежуточный набор из двух целевых вердиктов и добавляет `y`.
- Результат сохраняется в `data/processed/iavd_binary_labeled.parquet`.
- В набор вошли 197 746 карточек: 30 583 с `y = 1` и 167 163 с `y = 0`.

Промежуточный Parquet сохраняет все 94 исходных поля, в том числе поля категории C. До аудита и исключения утечки цели его нельзя подавать модели.

Запуск из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/prepare_binary_dataset.py
```

## Требуемый результат ML-трека

Интерактивное приложение на Taipy, интеграция модели с асинхронным инференсом и объяснения SHAP/PDP. В общей папке курса отдельный ML-файл модели `.joblib` не найден; если его предоставят отдельно, сверим его входные признаки с обновлённым словарём.

Черновик отчёта с описанием данных, эксперимента и выводов: [`report/otchet_ml.md`](report/otchet_ml.md).

## Приложение

В Taipy-приложении три страницы:

- **Обзор потока** — фильтры и графики только для целевых вердиктов «Решён» и `False Positive`; подписи дат показываются по месяцам, а время карточки — с точностью до секунды в UTC.
- **Модель-советчик** — асинхронная оценка карточек без вердикта и очередь по выбранному порогу. Здесь же показана отложенная проверка порога на более поздних карточках с известной меткой. Модель экспериментальная и не заменяет решение аналитика.
- **Диагностика модели** — дополнительное объяснение SHAP и PDP/ICE. Оно описывает поведение модели, а не причинность событий.

```bash
cd app
../.venv/bin/python main.py
```

После запуска открыть `http://127.0.0.1:5050`. При открытии страницы модели очередь для карточек без вердикта рассчитывается автоматически; порог сразу меняет число карточек и таблицу. Расчёт PDP/ICE запускается отдельно на странице диагностики.

## Базовая модель

В материалах курса готовый ML-файл `.joblib` не найден, поэтому подготовлена собственная базовая модель для дальнейшей проверки. Она использует 23 производных признака: 16 категориальных и 7 числовых. Модель не заменяет проверку на отложенных по времени данных.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/prepare_binary_dataset.py
.venv/bin/python scripts/build_baseline_features.py
.venv/bin/python scripts/train_baseline.py
```

Скрипт обучения сохраняет модель, метрики случайного и временного разбиений, тестовые предсказания и SHAP-выборку в `models/` и `data/processed/`.

Для оценки временного теста сформированы две таблицы:

- `outputs/monthly_model_evaluation.csv` — качество по месяцам, доля класса «Решён» и число ошибок.
- `outputs/temporal_policy_comparison.csv` — сравнение порога минимума стоимости `k·FN + FP` с максимумом `Fβ` при `β = √k`, для `k = 50` и `k = 100`, а также с правилами «проверять все» и «не проверять».

Временная проверка показала сдвиг доли класса «Решён»: 5,75% в июне, 17,51% в июле и 8,81% в ноябре 2025 года. Изменился и состав данных: в обучающем периоде были карточки MaxPatrol SIEM и Ankey SIEM NG, а в последнем тестовом периоде все 39 550 карточек относятся к Ankey SIEM NG. Среди исторических карточек Ankey доля «Решён» была 12,65% в обучении и 3,31% в периоде настройки порога, затем стала 12,30% в тесте.

Для порога минимальной стоимости и максимума Fβ расчёт выполняется на калибровочном временном отрезке, а сравнение — на более позднем тестовом отрезке. В текущем прогоне оба способа выбрали одинаковый порог; на тесте он отправляет на проверку 49,81% карточек, а цена ошибок по сценарию `k = 50` выше, чем у правила «проверять все» (72 467 против 34 687). Эксперимент с обучением только на исторических карточках Ankey также не улучшил качество ранжирования на последнем периоде (AP 0,233; ROC-AUC 0,640 против AP 0,284; ROC-AUC 0,717 у базовой модели). Поэтому текущая модель — учебный baseline: временная проверка нужна, чтобы показать, насколько она обобщается на будущие данные, и не считать её готовой к автоматизации решений.

Пересчитать таблицы по сохранённым временным прогнозам:

```bash
.venv/bin/python scripts/analyze_baseline.py
```
